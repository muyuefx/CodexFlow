# Codex Flow

中文本地 Markdown 工作流管理器。双击 `Start.cmd` 启动，在浏览器或 Codex 侧栏打开 http://127.0.0.1:43127 。需要 Node.js 24.19 或更高版本（使用内置 SQLite）。

## 开始使用

1. 首次打开选择流程库目录，默认 `C:\Users\muyue\CodexWorkflows`。
2. 打开“从想法到交付”了解三级子流程；也可新建流程、添加节点并关联现有 MD。
3. “AI 生成”整理并复制提示词到 Codex，由 AI 经 MCP 保存流程草稿。此入口不会单独调用付费 API。
4. 点击节点的“输入”页定义模板属性；点击“建立实例”命名并填写本次数据，保存为“待执行”。点击“开始执行”选择已有实例，复制指令到已加载 MCP 和 Skill 的 Codex 对话；Codex 接手后才显示“进行中”。本次填写不改模板，选择执行不会重复建立实例。
5. 双击子流程进入内部。选中阶段可看运行依据、人工完成、阻塞或重做。

`Connect-Codex.ps1` 配置名为 `codex-flow` 的 HTTP MCP 并安装配套 Skill。修改连接后在 Codex 设置中重载 MCP 或使用新对话。服务需要保持启动；不会自动唤醒已停止的 Codex 对话。

## 文件与历史

- `flows/<id>/workflow.json` 是可读的流程定义导出。应用数据库保存版本；手工修改 JSON 后用界面的导入功能载入为独立副本，直接编辑导出文件不会自动替换活动定义。
- Markdown 保持普通文件；界面保存写回实际路径，旧内容、外部修改和冲突草稿进入 `history.sqlite`。
- 新建文档默认进入流程库 `documents`。移除节点只解除关联，归档不删除文件。
- 每次建立实例包含冻结的定义、MD、节点状态和事件。文档修改需暂停后预览影响，再应用到当前运行。
- MD 编辑器草稿保留在当前浏览器会话；流程画布需要点击保存。关闭有未保存画布修改的页面会提示。
- 导出 JSON 包含关联文档路径，跨机器使用时需重新关联本机 MD；不嵌入或复制项目文件。

## 自定义节点属性

每个节点都可添加短文字、长文字、数字、开关、选项、图片或资源选择属性；显示名称、提示、必填、默认值及数字范围均可编辑。字段定义保存在 `properties`，填写值保存在 `inputValues`，用户填写优先于默认值；点击“恢复默认值”可以清除覆盖。普通节点和子流程使用同一机制，AI 经 MCP 定义的属性也显示为相同表单。

图片可选择文件、拖入或粘贴，每张最多 10MB，每个属性最多 20 张，支持 PNG/JPEG/WebP/GIF。图片复制到流程库 `images`，修改来源图片不会改变已经保存的内容。资源库支持用户定义分类、说明和图片，例如基准岛屿或风格样例；节点可以限定某一分类。选中资源的元数据、图片及关联 MD 在运行启动时冻结。

子流程的“按数量展开”可绑定本节点整数属性（1–100），默认依次执行，也可配置独立资源下的并行。把 3 改为 4 后启动，会生成四份独立执行实例；运行画布上方可以选择第几份，全部完成才进入下游。多个节点引用同一子流程仍共享模板、执行状态独立。数量值与其他输入修改只影响新运行，应用到当前运行须先暂停并查看影响。

右键节点 → “修改该节点流程 · Codex”可复制节点、输入、连线及子流程数据；粘贴到 Codex 对话后继续描述修改要求。当前独立网页没有已接入的 Codex 输入栏接口，因此需要手动粘贴，不会自动发送消息。交接文本会标明未保存草稿和运行快照，AI 修改前须核对版本。

流程 JSON 导出包含属性定义、填写值和图片/资源 ID；它不是跨机器自包含包。换库或换机器时需要同时迁移整个流程库的 `history.sqlite`、`images` 和关联 MD，或重新上传/选择资源；缺失引用会阻止运行，不静默替换。

## 运行规则

节点“输出”页可声明正式产物；“输入”页可绑定上游输出。图片图集及程序化系统清单作为实例成果保存，进入下游时冻结，重试时使相关下游失效。`resources` 支持一个节点选择多个系统。完整接口、版本规则与系统登记字段见 [正式输出与程序化系统](OUTPUTS-AND-SYSTEMS.md)。

顺序、并行汇合、多层子流程均由服务端验证。普通节点可由 AI 或用户完成；人工验收节点拒绝 AI 完成。AI 必须逐项提供完成依据；整个流程由 AI 在全部必需节点完成后提交总结结束。

暂停是协作暂停，不终止 Houdini、UE、命令等外部操作；恢复前确认实际操作是否停止。服务重启后未结束的运行显示待恢复，不能自动完成。人工点击完成也不代表外部工具已经停止。

第一版没有条件路由、自动循环、自动唤醒、多用户或远程托管。所有节点均为必需阶段。保护当前运行的快照不受模板编辑影响。

## 工作流全局约束

每套流程顶部点“全局约束”，填写全程的工具选择、性能或质量原则并保存。支持多行文字；“填入 SOP / VEX 性能示例”是可选示例，不会自动写入其他流程。所有子流程和批量实例继承相同约束，节点右键交接与 AI 生成指令也携带它。

字段为 `WorkflowDefinition.globalConstraints`（可选、最多 20000 字），流程复制、JSON 导入导出和版本保存都包含它。每次运行冻结约束，`workflow_context` 每阶段显式返回，并要求 AI 在完成依据中说明适用约束的落实。运行视图可查看冻结版本；编辑后需暂停，在“应用新版”预览约束前后差异及全阶段重做范围，应用后仍保持暂停。旧结果留在历史。此机制给 AI 提供执行要求，服务无法自动判断任意自然语言原则是否已满足。

## 流程实例集

侧栏“流程实例集”按流程查看每次独立运行：冻结输入、参考图片、全局约束、MD 快照、用户及 AI 资料、阶段成果和旧轮次历史。可补充文字/JSON/附件，进入执行进度或导出实例 JSON。JSON 包含记录与附件索引，文件逐项下载；不会自动收集整个 Codex 对话。

MCP 新增 `workflow_instances` 和 `workflow_data_write`；上下文提供 instanceData。完成节点自动记录 evidence 并复制成果附件。网页一次上传总计 10MB，本地路径归档单文件最多 256MB；过大、缺失和外部链接仅保存状态与来源。文件按 SHA256 独立存放并校验，修改原文件不影响副本。写入采用 CAS 和 operationId，用户/AI 来源由入口固定；重试与改版保留旧轮次，不自动改写执行输入。

MCP 中 `workflow_instance_create` 建立待执行实例，`workflow_start(runId, expectedRevision, operationId)` 接手已有实例。旧版 `workflow_start(workflowId)` 不再支持；更新后重载 MCP 工具列表。尚无执行活动的旧实例迁移为“待执行”，保留 ID、输入与资料。暂停应用新版时保留本实例覆盖的输入，按新属性定义重新校验。

## Codex 内快捷入口

桌面 **Codex Flow** 快捷方式调用 `Open-In-Codex.ps1`：检查并启动本机服务，通过 Codex 浏览器深链接打开管理页，不创建实例或执行任务。

AGame 与 CodexFlow 项目的 `.codex/environments/environment.toml` 也配置了同名环境操作。2026-09-18 在当前安装版本的实际界面中确认：“设置 → 环境 → AGame5_8 → AGame”能读取该操作，但聊天顶部没有显示对应按钮，开启底部面板也无效。因此环境操作目前不能作为已可用的顶部快捷入口，不保证重启后出现。当前可用方式是桌面快捷方式，或在服务运行时点击聊天中的管理页链接。

启动脚本优先把深链接发送给正在运行的 Codex，避免这台机器上的 MSIX URL 唤起无响应；找不到进程时按已安装应用定位，不固定版本路径。操作命令沿用 Start.cmd 的单进程脚本执行参数，不修改系统执行策略。
